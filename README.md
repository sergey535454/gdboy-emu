# GB Emulator (Godot 4) — эмулятор Game Boy для Android

Полностью самописное ядро эмулятора оригинального Game Boy (DMG) на чистом GDScript,
без сторонних библиотек эмуляции. Написано с нуля под Godot 4.3+.

## Что реализовано

- **CPU**: полный набор инструкций Sharp LR35902 (все 256 основных опкодов + 256 CB-префиксных),
  флаги, прерывания (VBlank/STAT/Timer/Serial/Joypad), HALT/STOP, DAA.
- **PPU**: рендеринг фона, окна (window) и спрайтов (8x8 и 8x16, приоритет, флипы),
  режимы OAM/Transfer/HBlank/VBlank с тайминг-циклами, STAT-прерывания.
- **Game Boy Color (CGB)**: определение по заголовку ROM (0x143), второй банк VRAM,
  CGB-палитры фона и спрайтов (BCPS/BCPD, OCPS/OCPD, RGB555→RGB888), атрибуты тайлов
  (палитра/банк/флипы/приоритет из VRAM-банка 1), CGB-палитры спрайтов (8 палитр по OAM-атрибуту),
  переключение двойной скорости CPU (KEY1/STOP), банки WRAM (SVBK, 8×4KB), HDMA/GDMA
  (VRAM DMA, регистры 0xFF51–0xFF55). Корректные стартовые регистры CPU для CGB
  (A=0x11 вместо 0x01 — так игры отличают CGB от обычного Game Boy).
- **MMU**: полная карта памяти, echo RAM, DMA-перенос в OAM (0xFF46).
- **Картриджи**: ROM-only, MBC1, MBC2, MBC3 (+ упрощённый RTC-стаб), MBC5.
  Автоопределение по заголовку ROM (0x0147–0x0149).
- **Сохранения**: батарейные картриджи (MBC1+BATTERY и т.д.) сохраняются в файл `.sav`
  рядом с ROM автоматически при смене игры или закрытии приложения.
- **Таймер**: DIV/TIMA/TMA/TAC с прерываниями.
- **Джойпад**: сенсорные D-pad/A/B/Start/Select на экране (полноценный мультитач — можно
  держать несколько кнопок одновременно) + клавиатура для теста в редакторе
  (стрелки, Z=A, X=B, Enter=Start, Shift=Select).

## Чего нет (сознательные упрощения)

- **Звук (APU) не реализован** — регистры звука существуют как заглушки (чтение/запись без звука),
  чтобы игры не зависали при обращении к ним, но реального звука нет.
- CPU-тайминг приближённый (не 100% cycle-accurate по T-состояниям на каждую операцию),
  поэтому часть игр с очень строгими тайминг-трюками может работать некорректно.
- **HDMA/GDMA выполняется мгновенно целиком**, а не по 0x10 байт за каждый H-Blank, как на
  настоящем железе. Итоговый результат обычно совпадает (VRAM всё равно обновляется только
  во время гашения экрана), но это не cycle-accurate поведение.
- **Двойная скорость CGB** реализована упрощённо: PPU/таймер получают половину тактов CPU
  в режиме x2, что даёт корректную частоту кадров и в целом верную скорость игры, но не
  воспроизводит тонкости реального поведения регистра DIV в режиме двойной скорости.
- RTC в MBC3 — минимальный стаб без реального хода времени между запусками.

Это рабочая база: CPU/PPU/MMU/MBC написаны честно и по структуре опкодов, а не заглушками,
так что большинство несложных коммерческих и почти все homebrew/тестовые ROM должны запускаться —
включая CGB-игры с цветной графикой. Для доводки до идеала обычно нужны недели тестирования на
реальных играх и тест-ROM (blargg's tests, Mooneye GB test suite, dmg-acid2/cgb-acid2 и т.п.) —
эта база даёт с чего начинать и куда добавлять точность.

## Важно: легальность ROM-файлов

Сам по себе эмулятор совершенно легален — эмуляция консолей не запрещена. **Но играть можно
только в ROM-файлы, которые вы сделали сами со своих оригинальных картриджей** (дампер вроде
GB Operator/Retrode) **или которые находятся в открытом доступе легально** (гомебрю-игры,
демо, паблик-домейн). Скачивание образов коммерческих игр, которыми вы не владеете — нарушение
авторских прав. Я не могу предоставить сами ROM-файлы Nintendo — это придётся сделать
самостоятельно и на свой ответственный выбор.

## Как открыть и запустить

1. Установите **Godot 4.3+** (Standard, не .NET — весь код на GDScript): https://godotengine.org/
2. Откройте папку проекта (`project.godot`) через "Import" в Project Manager.
3. Нажмите **F5** — запустится сцена `Main.tscn` в окне рабочего стола (удобно для быстрой проверки).
4. Загрузите `.gb`/`.gbc` файл через кнопку **"Загрузить ROM"**.

## Как собрать APK для Android

1. В Godot: **Editor → Manage Export Templates** → скачайте шаблоны экспорта под вашу версию Godot.
2. Установите Android SDK (проще всего через Android Studio) и укажите пути в
   **Editor → Editor Settings → Export → Android** (Android SDK Path, debug keystore создаётся
   автоматически при первом экспорте).
3. **Project → Export...** → **Add... → Android**.
4. В настройках Android-пресета:
   - Permissions: включите `READ_EXTERNAL_STORAGE` / `MANAGE_EXTERNAL_STORAGE` (или используйте
     scoped storage — см. ниже), чтобы можно было выбрать ROM через системный диалог.
   - Orientation уже выставлена как portrait в `project.godot`.
5. **Export Project** → выберите путь → получите `.apk`, установите на телефон
   (`adb install game.apk`) или скопируйте и установите вручную (разрешите установку
   из неизвестных источников).

### Как закинуть ROM-файл на телефон

Проще всего:
```
adb push my_game.gb /storage/emulated/0/Android/data/<package_id>/files/roms/
```
(`<package_id>` — имя пакета из настроек экспорта, по умолчанию `org.godotengine.gbemulator`
или то, что вы укажете). Либо используйте кнопку "Загрузить ROM" — она открывает системный
файловый диалог Godot (`FileDialog`), которым можно перейти в любую доступную папку,
если приложению даны разрешения на доступ к файлам.

## Структура проекта

```
project.godot
scenes/Main.tscn          — сцена с UI и экраном
scripts/main.gd           — игровой цикл, UI, сенсорное управление, загрузка ROM
scripts/emulator/cpu.gd       — процессор Sharp LR35902
scripts/emulator/mmu.gd       — карта памяти
scripts/emulator/ppu.gd       — видео (фон/окно/спрайты)
scripts/emulator/timer.gd     — таймер DIV/TIMA
scripts/emulator/joypad.gd    — кнопки
scripts/emulator/cartridge.gd — ROM + MBC1/2/3/5 + сохранения
scripts/emulator/gameboy.gd   — оркестратор, связывает всё вместе, игровой цикл на кадр
```

## Что можно доработать дальше

- Добавить APU (звук) — 4 канала (2 pulse, wave, noise), это отдельный большой модуль.
- Точный cycle-accurate тайминг CPU (сейчас используется общий M-cycle подход) и настоящее
  по-строчное (не мгновенное) HDMA.
- Save states (сериализация полного состояния CPU/MMU/PPU в файл) — сейчас есть только
  сохранение картриджного RAM (как на настоящем картридже с батарейкой).
- Экранные шейдеры под "LCD-сетку" для более аутентичного вида.
